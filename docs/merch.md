# Мерчендайзинг

Раздел админки «Мерчендайзинг» (`apps/backend/src/admin/routes/merch`). Сейчас — основа: план зала и оборудование.

- Варианты расстановки — модуль `merch` (таблица `merch_layout`: название, `data` JSON, `is_current`). API: `/admin/merch/layouts`, `/admin/merch/layouts/:id`.
- Содержимое варианта (`apps/backend/src/admin/lib/merch/catalog.ts`): зал (размеры, высота в коньке и у стен — мансарда, отделка стен, двери/окна), оборудование (тип, центр x/y в метрах от левой и верхней стены, поворот, размеры, высота крепления), зоны (сила места 1–5), подложка-картинка.
- Каталог оборудования собран по фото магазина: пристенные системы, стойки на плите, стойки из труб, круглые стойки, стеллажи из труб, металлические шкафы, П-образные полки 60 и 40 см, сетка, столы, пуфы, манекен, примерочные, касса, колонны, перегородка, треки света. Всё — нержавейка.
- План (`plan.tsx`, SVG): перетаскивание, прилипание к стенам, шаг 1 см, зоны с изменением размера. 3D (`scene.ts`, three.js): «кукольный домик» с прячущимися стенами, обход зала от входа, перетаскивание в 3D, снимок PNG. Вещи на вешалах — пример (случайные цвета), не реальные товары.
- Первый вход создаёт черновик по присланному плану; размеры примерные до замеров.

## Товары на оборудовании

- `data.assign`: id оборудования → список `{ p: товар, n: вешалок/мест, place: rail|shelf }` по порядку.
- «Разложить товары» — `src/lib/merch/autofill.ts` (чистая функция, тесты рядом): сила места = звёзды зоны + близость ко входу;
  туда — товары с высшим баллом умной сортировки (сезон уже в балле); одна стойка — один бренд (второй — если первый занял < 70 %),
  повтор бренда штрафуется ×0,75; на стойке — по категориям, внутри от светлого к тёмному; вешалок на модель — по числу размеров (до 3).
  Обувь — на стеллажи из труб, сумки/кепки — шкафы, сетка, полки; столы — сложенное и аксессуары; манекен — образ одного бренда.
  Закреплённое оборудование не трогается, у оборудования можно ограничить категории и бренды.
- Товары для раскладки: `GET /admin/merch/products` (в наличии, не предзаказ, с баллом). Склад общий с сайтом — система не знает,
  что физически в зале; консультант видит размеры в наличии.
- В 3D вещь получает вид по категории и цвет по цвету товара (`kindOf`, `COLOR_HEX`).

## Задания консультантам

- Модель `merch_task` (шаги JSON, секретный token). Создаются в админке: шаг на каждое оборудование с товарами
  (или только изменения относительно текущей расстановки), картинка из 3D (снимок спереди → файл), текст простыми словами (`stepText`).
- Консультант: `https://<ADMIN_DOMAIN>/staff/merch/<token>` — страница для телефона без входа (`lib/merch/staff-page.ts`):
  отметка «Сделано», фото (уменьшается в браузере до 1600 px). Когда всё сделано — сообщение в Telegram магазина.
- Мерчендайзер: «Задания консультантам» внизу раздела — прогресс, фото, замечание, «Принято»/«Переделать» (снимает отметку), закрыть.
  Кнопка «В рабочий чат» шлёт ссылку в чат из «Смен».
- Дальше: смена сезона (сравнение вариантов уже есть через «Только изменения»), отчёт «что не попало в зал».

## Правила, образы, стандарты, чек-листы, проверка

- Настройки — `merch_settings` в metadata магазина (`lib/merch/settings.ts`, `/admin/merch/settings`): уровни (плотность, размеры,
  лицом вперёд, места на полке), бренды (уровень, стиль, якорный), стандарты магазина, образы, чек-листы.
- Образы (`looks`): манекен — вещи образа повиснут на ближайшей стойке первыми; стол; начало стойки. Ставятся до остальной раскладки.
- Стандарты (`standards`): строки по типам оборудования, добавляются к шагам задания (`standardsFor` в `tasks.ts`).
- Чек-листы (`checklists`): задача `merch-checklists` раз в минуту создаёт задание-чек-лист (layout_id `checklist:<id>`) по расписанию
  (Омск, не позже 3 часов) и шлёт ссылку в рабочий чат из «Смен» с упоминанием тех, кто на смене. «Отправить сейчас» — вручную.
- Проверка расстановки (`lib/merch/checks.ts`, тесты рядом): пересечения, за стеной, проход уже 80 см, перекрытый вход (120 см),
  высокое (> 1,4 м) в 3 м от входа, подход к примерочным и кассе. Колонны и перегородка — как стены. Только предупреждения.
- Печать задания: `/staff/merch/<token>?print=1` — страница для печати / PDF с квадратиками для отметок.

## Продажи магазина: офлайн-балл, роли, план площади, довешивание, отчёт

- `merch_sale` — розничные чеки МоегоСклада (без сайта и отгрузок) по дням (Омск) и размерам за 60 дней, минус возвраты.
  Задача `merch-retail` каждую ночь (03:20 по Омску) пересчитывает целиком; кнопка «Обновить продажи» в отчёте — вручную.
- Офлайн-балл (`lib/merch/offline.ts`): продажи магазина (лог), маржа (закупка из МС), остаток, полнота размеров, новизна, сезон
  (составляющая Z умной сортировки). Роли: новинка, хит, хит без размеров, второй шанс, база, не сезон, распродажа.
  Без продаж магазина — балл сайта и только роли новинка / не сезон / распродажа / база.
- Роли в раскладке: «второй шанс» ×1,6 в сильных зонах (4–5 звёзд); хит без размеров — ×0,5 в сильных, ×1,3 у примерочных;
  не сезон — ×0,2 везде, кроме дальней зоны.
- План площади (`areaShares`, `areaTargets`): доля стоек бренда = вес × доля продаж магазина за 60 дней + (1 − вес) × доля остатка
  одежды; ручная доля в % важнее; якорному — не меньше 2 стоек. Бренд, выбравший свою норму, почти не берётся.
- Довешивание (`lib/merch/replenish.ts`): в заданное время — задание «Довесить» по продажам вчера из текущей расстановки, в рабочий чат.
- Отчёт (`lib/merch/report.ts`, `GET /admin/merch/report`): выручка за 30 дней по оборудованию (на метр штанги / место полки),
  зонам, брендам; сильные товары не в зале; «второй шанс» — 14 дней против предыдущих 14.
